# Proposal: 会话库可视区懒加载与缩略图缓存

## 1. Context & Problem Statement

- **Current State**: “全部录制”会一次性渲染所有会话卡片；每张可用卡片立即挂载 `video preload="metadata"`，同时请求录屏媒体、探测时长并定位首帧。
- **Pain Points**: 会话数量增长后，进入列表会同时触发大量媒体请求、解码器和 React/Motion 节点，首屏明显卡顿；简单卸载离屏视频又会导致滚回时重新读取。

## 2. Value Proposition

- 首屏只处理可视区域与少量预取缓冲，快速显示可操作的会话库。
- 将首次提取的首帧保存为轻量 WebP 派生缓存，后续打开和回滚只渲染图片。
- 动态视频预览只在悬停时临时创建，移开后释放解码资源。
- 缓存位于应用数据目录，可重建且不污染原始录制会话。

## 3. Alternatives Considered

- **一次性保留所有 `<video>`**：滚回无需加载，但媒体请求、解码器和内存占用随会话数线性增长，不能解决首屏卡顿。
- **纯虚拟列表并彻底卸载视频**：资源有界，但滚回时需要重复读取 metadata 和首帧，交互易出现白屏与抖动。
- **只用 `IntersectionObserver` 切换 `preload`**：减少首屏请求，但每次回滚仍可能重新读取，且没有跨启动收益。
- **选定方案：增量卡片 + 持久缩略图缓存**：可视区首次提取并持久化 WebP/时长，卡片常态使用图片，悬停视频按需挂载。

## 4. Success Metrics

- [ ] 首屏媒体请求数量只与首屏卡片及缓冲区相关，不随全部会话数增长。
- [ ] 已生成缓存的会话再次进入列表时不为静态卡片加载录屏视频。
- [ ] 滚回已浏览区域立即显示缩略图，不重复提取首帧。
- [ ] 永久删除、清空回收站和移除失效索引后不残留对应缓存。
