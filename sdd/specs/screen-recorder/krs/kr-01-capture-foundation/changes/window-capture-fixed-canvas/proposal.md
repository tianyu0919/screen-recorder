# Proposal: 窗口录制固定画布与动态几何 (Proposal)

## 1. Context & Problem Statement

- **Current State**: 窗口录制复用整屏坐标换算，只保存显示器 bounds 和录制开始时的视频尺寸；窗口移动、缩放或最大化后，点击与鼠标事件仍按显示器原点映射，捕获轨尺寸变化也会让固定时间线画布失真。
- **Pain Points**: 点击波纹、自动运镜和鼠标跟随偏离真实位置；小窗口开始录制后最大化会导致预览比例和分辨率异常；同一 WebM 中尺寸变化使预览与 MP4 导出不稳定。

## 2. Value Proposition

- 让窗口录制在 macOS 与 Windows 上移动、缩放和最大化时仍保持稳定画布与准确点击反馈。
- 统一波纹、鼠标跟随和自动运镜的坐标来源，避免三套逻辑漂移。
- 为 2K/高 DPI 显示器保留足够原始清晰度，同时允许导出降为 1080p。

## 3. Alternatives Considered

- **只修波纹坐标**：拒绝。自动运镜和鼠标跟随仍错误，窗口尺寸变化仍破坏视频。
- **以初始窗口尺寸作为固定画布**：拒绝。小窗口开始后最大化会被初始低分辨率限制清晰度。
- **允许 WebM/MP4 中途动态分辨率**：拒绝。播放器、时间线、WebCodecs 和 MP4 编码都依赖恒定画布。
- **固定为窗口所在显示器物理分辨率**：采用。来源变化只影响画布内摆放，文件尺寸保持稳定。

## 4. Success Metrics

- [ ] macOS 与 Windows 的窗口录制中，点击波纹在移动、缩放和最大化前后均落在真实点击区域。
- [ ] 窗口来源变化期间录制文件分辨率恒定，预览和导出无拉伸、裁切或画面跳变。
- [ ] 2K 显示器上的窗口录制可保留 2560×1440 固定画布并正常导出。
- [ ] 整屏录制和旧 V1 会话无回归。
