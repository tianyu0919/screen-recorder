# Verification Checklist: 麦克风权限与可选录制流程

## Functional Verification

- [x] 仅麦克风未授权时，首页仍显示独立的未授权状态和授权入口，并明确其为可选能力。
- [x] 麦克风权限不是 `granted` 时开关默认关闭，不呈现虚假的可用状态。
- [ ] `unknown` 状态下打开开关会立即触发一次 macOS 系统授权请求；同一次操作不会重复请求。
- [ ] 首次授权成功后权限状态刷新，麦克风开关开启且可正常录制 `mic.wav`。
- [ ] 已拒绝状态下点击麦克风操作会打开正确的系统设置面板，开关保持关闭。
- [ ] 从系统设置授权后点击“重新检查”，麦克风状态独立变为绿色成功。
- [ ] 已授权状态被撤销后重新检查，麦克风开关自动关闭。
- [ ] 麦克风关闭时可正常开始和结束录制，过程中不弹授权框，会话不包含 `mic.wav`。
- [ ] 麦克风采集在开始前意外失败时显示中文提示，并安全降级为无麦克风录制。
- [x] 开始录制与写入 `mic.wav` 不再承担首次麦克风授权。

## Compatibility & Safety

- [x] 屏幕录制和辅助功能权限的既有申请、刷新及降级行为无回归。
- [x] Windows 保持现有可录制行为，不调用 macOS 专属权限 API。
- [x] Main、preload 与 Renderer 只使用 `shared/` 中的 IPC 契约，不透传 `ipcRenderer`。
- [x] 无麦克风权限不会阻断画面、系统音频、鼠标轨迹或已授权的输入事件采集。

## Code Quality & Testing

- [x] 相关源文件均不超过 300 行，无调试日志或无关重构。
- [x] 权限状态分支具备自动回归或可重复的纯状态测试。
- [x] `npm run typecheck` 通过。
- [x] `npm run build` 通过。
- [ ] macOS 实机完成首次授权、拒绝、系统设置返回、撤权和无麦克风录制冒烟。
