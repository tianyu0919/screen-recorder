# Proposal: 火山引擎云端高清 TTS

## 1. Context & Problem Statement

- **Current State**: kr-08 已提供随安装包分发的本地中英 TTS，并以本地模型作为默认引擎。部分用户对自然度、连续性和音色表现有更高要求，但继续增加大型本地模型会显著扩大安装包，并提高双平台运行时与硬件适配成本。
- **Pain Points**:
  - 内置模型必须兼顾包体、离线能力和低硬件门槛，音质上限有限。
  - 当前 `cloud` 引擎只有契约占位，用户无法选择云端高质量音色。
  - 云端接入涉及第三方数据传输、用户自有凭据、本地密钥安全和潜在计费，不能按普通模型选项处理。
  - 火山账号的套餐和音色权限不同，单一固定音色列表无法覆盖所有用户。

## 2. Value Proposition

- 保持本地模型默认、离线即用，同时为需要更高自然度的用户提供明确可选的云端路径。
- 用户使用自己的火山引擎 API Key，费用和服务权限归属清晰。
- API Key 仅在本机通过 Electron 系统安全存储加密保存，不进入普通设置、前端持久化状态或日志。
- 精选中英文音色降低首次配置门槛，自定义音色 ID 与资源 ID 兼容不同套餐和后续服务变化。
- 分段缓存复用已成功音频，减少重复请求、等待时间和潜在费用。

## 3. Alternatives Considered

- **只保留本地模型**：隐私和离线能力最好，但无法满足用户对更高自然度音色的需求。
- **把更多大型模型塞入安装包**：无需发送文本到第三方，但会明显增加包体、安装时间、内存占用和双平台适配成本。
- **由应用提供统一服务端密钥**：用户使用简单，但会引入服务端成本、凭据托管、滥用控制和额外隐私责任，不符合用户自带 Key 的要求。
- **只提供固定音色列表**：界面简单，但用户套餐可能没有对应权限，也无法使用控制台中已开通的自定义音色。
- **整段字幕一次合成**：跨句衔接更自然，但首版难以在不新增强制对齐能力的前提下精确映射现有字幕时间窗。

## 4. Success Metrics

- [ ] 未配置云端时，本地内置模型仍默认可选、离线可生成，现有流程无回归。
- [ ] 用户可用新版单 API Key 完成保存、测试、精选音色生成及自定义音色 ID 生成。
- [ ] 明文 API Key 不写入 `settings.json`、编辑文档、缓存键或日志，Renderer 也无法回读已保存密钥。
- [ ] 第一次发生云端文本传输前有明确披露与同意，界面准确显示字幕段数和字符数。
- [ ] 文本、音色、资源 ID 和凭据修订未变化时命中本地分段缓存，不重复调用云端。
- [ ] 网络或服务端失败不会静默混入本地音色，也不会覆盖已存在的可用派生轨。
