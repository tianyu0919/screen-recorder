# Proposal: 编辑预览清晰度与性能提醒

## 1. Context & Problem Statement

- **Current State**: 普通编辑模式的 WebGL backing 最高限制为 `1280×720`，并固定按 `1x` CSS 像素渲染；专注预览才会结合设备像素比提高到最高 `2560×1440`。会话卡片的时长叠在缩略图上，容易被亮色内容干扰。
- **Pain Points**: Retina 或高分辨率屏幕上的普通编辑画面明显发糊，用户只能进入专注预览才能检查细节；直接永久提高 backing 又可能让低性能设备播放卡顿；现有界面没有可控分档、性能反馈或快速降档入口；会话卡片时长在部分缩略图上对比度不足。

## 2. Value Proposition

- 让用户在编辑过程中按设备与任务选择清晰度，不必频繁进入专注预览。
- 通过“自动”默认档兼顾 Retina 清晰度和一般设备性能，并保留明确的手动控制。
- 在确认发生持续卡顿后给出可操作、非阻塞的降档提示，不擅自改变用户选择。
- 提高会话时长信息在任意明暗缩略图上的可读性。

## 3. Alternatives Considered

- **所有编辑预览固定为 1080p/1440p**：实现简单，但会在低性能设备和高分辨率源上永久增加纹理上传与合成开销。
- **只提供“高清”开关**：状态含义粗糙，无法覆盖 Retina 自动适配和主动追求 1440p 的用户。
- **检测卡顿后自动降档**：恢复流畅最快，但会在用户不知情时改变画质，且可能造成播放中突然变糊。
- **页面内固定 Alert**：操作清晰，但会挤占本就有限的预览高度。最终采用顶部居中的 shadcn Sonner Toast。
- **将清晰度写入 `edit.json`**：能按会话保存，但清晰度是本机性能偏好，不属于导出内容，跨设备同步会产生错误语义。

## 4. Success Metrics

- [ ] 普通编辑模式可选择自动、流畅、高清、超清四档，并在重启应用后保留选择。
- [ ] Retina 下默认自动档最高使用 1080p backing，普通编辑画面不再固定停留在 720p。
- [ ] 持续卡顿会触发一次可操作 Toast，暂停、跳转、后台和专注预览不误报。
- [ ] 清晰度设置不修改 `edit.json`、最终导出尺寸或导出质量。
- [ ] 会话卡片时长移入正文元数据行，在明暗缩略图与深浅主题下均清晰可读。
