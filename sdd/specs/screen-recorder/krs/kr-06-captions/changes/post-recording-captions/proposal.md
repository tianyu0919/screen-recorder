# Proposal: 录制后离线字幕生成与编辑

## 1. Context & Problem Statement

- **Current State**: Lenza 已把麦克风保存为与视频源时间轴对齐的 `mic.wav`，并已有字幕 KR 草案，但原方案同时包含录制中实时字幕、悬浮窗和停录后双遍识别，首期范围过大。
- **Pain Points**:
  - 用户录制结束后仍需借助外部工具生成字幕，再手工与 Lenza 的裁剪和导出结果对齐。
  - 实时字幕会引入 AudioWorklet、实时背压、不可捕获悬浮窗及双平台窗口差异，显著增加录制主链路风险。
  - 字幕若不进入源时间轴和统一合成器，就无法保证编辑预览、MP4 与 SRT 一致。

## 2. Value Proposition

- 先以录制后的完整 `mic.wav` 离线转写，避免影响录屏稳定性并缩短交付路径。
- 转写任务独立于编辑页面生命周期，用户可切换会话并查看进度、取消或重试。
- 字幕以源时间轴持久化，可与非破坏式裁剪、预览和导出共用同一映射。
- 默认本地处理，不上传原始麦克风内容。

## 3. Alternatives Considered

- **保留实时 + 最终双遍识别**：反馈及时，但会把推理负载和窗口管理带入录制热路径，首期不采用。
- **云端转写 API**：接入快、准确率可控，但依赖网络、持续计费并上传音频，不作为默认方案。
- **系统语音 API**：安装体积小，但 macOS/Windows 的语言、时间戳与能力不一致，平台语义难统一。
- **选定方案：录制后本地 whisper.cpp**：用户在编辑页按需触发完整 WAV 转写；模型按需下载，Main 管理后台任务，完成后原子写入 `captions.json`。

## 4. Success Metrics

- [ ] 字幕关闭、取消或失败不影响录屏、预览和无字幕导出。
- [ ] 有麦克风的历史及新会话都可在编辑页按需生成字幕。
- [ ] 页面切换不丢失任务状态，同一会话不会并发启动多个转写任务。
- [ ] 字幕修改、裁剪映射、MP4 烧录和 SRT 输出使用同一字幕文档。
- [ ] Windows 与 macOS 均完成模型下载、离线转写、编辑和导出闭环。
